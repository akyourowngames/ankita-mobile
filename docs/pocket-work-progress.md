## Notification module completed

Owned files: server/work-push.mjs, src/work/notifications.ts, test/work-notifications.test.mjs. Server interface createPushDelivery({ store, fetcher = fetch, now = Date.now }) returns tick(). Each send claim is atomically persisted before requesting Expo; actual tickets become accepted, actual APNs/FCM receipts become provider_received, and neither claims phone display. Definite service rejection receives bounded exponential backoff; receipt lookup retries never resend accepted alerts. Ambiguous network/JSON/oversize outcomes, interrupted sends and lost ticket persistence become uncertain for manual review instead of automatic duplicate sends. DeviceNotRegistered revokes only the matching stale device token, preserving newly refreshed registrations. Fixed URLs, request deadlines, 64 KiB response bounds and generic private lockscreen text are used. Source protocol checked against https://docs.expo.dev/push-notifications/sending-notifications/ and installed expo-notifications declarations.

Native interface createWorkNotifications(platform, loader?) returns supported, requestPermission(), register(projectId), present({ workId, eventId }), test(), attachOpenHandler(handler), clear(). Register requires a real UUID project ID and returns the actual Expo token. Present checks existing permission without prompting, coalesces repeated calls, uses deterministic local event IDs, and recognizes an already displayed remote event by eventId. Clicks support both current native listeners and cold-start responses. Clear cancels/dismisses only validated work alerts, preserves task reminders, and cleans up a local schedule resolving after disable/reset. Browser reports native notifications unsupported.
